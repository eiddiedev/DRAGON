# 网络模型 - Shared Mode

## 一、Shared Mode 概念与分布式模型

**Shared Mode（共享模式）** 是 Douyin World 默认使用的**分布式联网模式**。和传统的 Client-Server 模式不同，在 Shared Mode 模式下，**房间里没有独立的服务器进程**。所有玩法逻辑分散运行在每个玩家的客户端上，每个客户端承担一部分"服务器角色"。
**核心模型可以概括为：分布式计算 + 主权制**。

### 去中心化计算与房间服务器职责
- **代码副本**：每个客户端执行**完全相同的一份**业务代码。
- **状态一致性**：通过**同步变量**自动同步，补以 **RPC**（`SendMessageToXxx`）做通知。
- **房间服务器职责**：仅负责消息转发（RPC/同步变量增量）和数据存储，**不执行任何业务逻辑代码**，**不做任何合法性校验**。
- **关键计算的执行方**：由持有对象**主权（Ownership）**的客户端执行权威逻辑（如修改同步变量），其它客户端只能读取或请求主权方代跑。
- **分布式管理器原则**：**中心化管理器不适用**。由于主权在客户端之间流转，若强行让房主承担"中心节点"角色，主权转移（如房主退房、切后台）与网络异常会导致数据丢失或逻辑中断。Shared Mode 下应使用**分布式管理器**设计（即各客户端本地维护状态，通过同步变量协商决策）。

## 二、主权分配规则

Shared Mode 中每个网络对象都有一个"主权方"（Owner），只有主权方可以修改这个对象的同步变量。
- **场景静态对象**：场景中摆放好的公共网络对象（如 NPC、道具箱），由房间自动调度，第一个进房的玩家（房主）默认持有。随着玩家进出可能分散到多个客户端。
- **动态生成对象**：客户端调用 `DouyinObjectService.NetSpawn` 生成的对象，主权默认归调用方客户端。
- **玩家关联对象**：玩家操控的 `DouyinActor`（角色）主权永远归该玩家自己。
- **主权释放与转移**：
  - **玩家退房**：该玩家持有的所有主权由房间自动转移到其它客户端。
  - **玩家切后台/断线**：该玩家持有的主权对象**暂时不可修改**，直到房间感知并完成主权转移到另一个在线客户端。业务侧应当避免让“关键权威逻辑”长期挂在单个主权方上。
  - **修改前提**：修改同步变量前必须调用 `HasOwnership()`（Lua）/ `IsOwner()`（C#）确认主权。

## 三、网络通信机制

Shared Mode 下**没有“客户端 ⇄ 服务器”通道**（因为没有独立服务器），只有“客户端 ⇄ 客户端”通道：

### 1. 通信方式
- **同步变量**：用于持续存在的状态（如生命值、得分、道具数量）。值变化时自动同步（70ms–120ms 延迟），平台保证**最终一致性**，即使弱网或断线，重进房后能拉取到最新值。**写前必须判定主权**。
- **RPC 通信 (`SendMessageToXxx`)**：用于次要的通知类消息（如游戏开始提示、临时特效触发）。事件驱动，即时发送，基于 TCP 可靠传输，但**不保证送达**（接收方断线时不补发）。核心状态绝对不能依赖 RPC 传递。

### 2. 代码“特定端执行”的做法
Shared Mode 下没有任何代码是“只在服务器端执行”的，所有代码都在客户端运行。如果需要限制执行端，通过运行时判定：
- **只在主权方执行**：通过 `HasOwnership()`（Lua）/ `IsOwner()`（C#）判断。用于修改同步变量、执行权威逻辑。
- **只在本地玩家执行**：通过 `actor.isLocal` / `player.isLocal` 判断。用于播放本地音效、显示本地 UI、订阅本地输入。
- **主动委托到主权方**：非主权方希望修改状态时，通过 `DouyinScript.SendMessageToOwner` 请求主权方代跑，主权方在方法中完成对同步变量的修改。

## 四、数据存储 (DataStore) 与防作弊

- **客户端直接调用**：Shared Mode 下，客户端脚本可**直接**调用 DataStore API，不像 DS 模式有强制的调用位置约束。
- **并发保护**：由于没有独立服务端，常见的工程规范是**“仅由主权方负责读写”**，以避免多个客户端同时写入引发数据覆盖。
- **防作弊约束**：由于客户端可以篡改本地代码和内存，这种方式**无法防作弊**。涉及**虚拟资产、付费购买、排行榜积分**的持久化写入，**都应当直接迁移到 DS 模式**，不应在 Shared Mode 下自行增加本地保护。

## 五、常见问题 (FAQ)

**Q1：Shared Mode 下有独立的服务器进程吗？**
没有。房间服务器只做消息中继与数据存储，不执行任何业务代码。业务逻辑全部在客户端上分布式执行。

**Q2：Shared Mode 下 `DouyinApplication.isServer` 会返回 `true` 吗？**
永远为 `false`。这个字段只在 DS 端为 `true`。Shared Mode 下想做"某段代码只在特定端执行"，应改用 `HasOwnership()` 或 `actor.isLocal`。

**Q3：Shared Mode 下能用 `DouyinRemoteEvent / DouyinRemoteFunction` 吗？**
不能。这两个对象专用于 DS 模式的客户端 ⇄ 服务器通信。Shared Mode 客户端间通信请用 `DouyinScript.SendMessageToXxx`。

**Q4：Shared Mode 下 `SendMessageToXxx` 一定送达吗？**
不一定。RPC 基于 TCP 可靠传输，但接收方断线时**不补发**。关键状态请必须通过**同步变量**传递。

**Q5：Shared Mode 下主权方断线，其对象怎么办？**
主权方断线时，该对象的同步变量**暂时不可被任何客户端修改**，直到房间服务器感知断线并完成主权转移到另一个在线客户端。业务侧应当避免让"关键权威逻辑"长期挂在单个主权方上。

**Q6：Shared Mode 场景里能挂 `DouyinServerRoot` 吗？**
不能。一旦挂上 `DouyinServerRoot`，场景就切换为 DS 模式。想让一个 DS 场景"退回"到 Shared Mode，必须移除 `DouyinServerRoot` 节点并清空服务器专属脚本载体。
