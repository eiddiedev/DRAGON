# 同步变量

**同步变量**（Sync Variable）可以用于自定义**网络对象**的属性、在**房间维度**同步的网络数据，例如一个数字、一个位置或者一段文字。声明后，该变量的值由**主权方**负责维护和推送，当同步变量所存储的数据变化时，房间内所有玩家都将会同步数据的变化。

## 核心特征

- **房间维度**：变量的值属于房间上下文，房间内**所有玩家**（含后加入者）都会看到同步后的值。
- **主权驱动**：只有网络对象的**主权方**可以写入变量值，非主权方只能读取。
- **可靠传输**：保证同步过程**不丢包**，主权方的每一次成功写入，最终都会送达其他客户端。
- **宿主限制**：同步变量属于**网络对象**的能力延伸，因此声明它的宿主必须是一个网络对象。若宿主不是网络对象，同步变量声明将不生效。

## 支持的变量类型

### 基础值同步变量
- **Lua** (`---@varSync`)：`bool`, `byte`, `short`, `int`, `long`, `float`, `double`, `string`, `Vector2`, `Vector3`, `Quaternion`.

### 集合同步变量
- **Lua** (`List` / `Dictionary`)：
  - `List` 元素类型支持：`bool`, `byte`, `short`, `int`, `long`, `float`, `double`, `string`, `Vector2`, `Vector3`, `Quaternion`。
  - `Dictionary` 键（Key）支持：`byte`, `short`, `int`, `long`, `string`；值（Value）支持同 `List`。

> **⚠️ 注意**：不支持结构体或复杂的自定义类（如 Lua table）。如果业务需要同步一个复合数据，建议将其 JSON 序列化成 `string` 存储，在 `OnValueChange` 变化监听回调中进行反序列化。如果业务逻辑强依赖多个同步变量的组合状态才能正确执行，必须同时侦听所有相关同步变量的变化，等待数据全部就绪后再执行逻辑。

## 创建变量

同步变量必须被声明为脚本类的成员，不能作为局部变量使用。

### Lua 声明方式
使用 `---@varSync` 开头，表示声明一个同步变量。这些声明通常放在脚本文件头部。
> **⚠️ AI Editor 规范**：一个脚本文件只能有一个 `---@start` 和一个 `---@end`。普通变量 `---@var` 与同步变量 `---@varSync` 必须放在同一个声明块中；`---@var` 必须声明对应的 `---@name`。

```lua
---@start
---@var energyBallKey:string
---@name 能量球键
---@varSync intValue:int
---@varSync vectorValue:Vector3
---@varSync listSync:List<int>
---@varSync dictionarySync:Dictionary<int,string>
---@end
```

## 访问和设置同步变量

同步变量的写入权限**只属于当前网络对象的主权方**。

**读写规则与时序说明：**
1. **主权方操作**：主权方可以执行读值、写值以及集合的所有增删改操作。写入前需使用 `self:HasOwnership()` 确认当前端具备主权。
2. **非主权方操作**：非主权方只能读取值、读取集合元素个数、遍历等。**如果非主权方直接调用修改接口，会被 SDK 静默忽略**；如果业务此时基于该值做后续判断，会导致本端与其他端状态错位。非主权方需要修改时，必须**将请求转发给主权方**，由主权方代为执行写入。
3. **写入后同步时序**：
   - **本端**：调用写入接口之后**立即**触发变化监听回调，不存在延迟。
   - **其他客户端**：需要等待 SDK 层网络同步到达后才触发变化监听回调，存在网络延迟。
4. **有效值窗口**：同步变量的**有效值窗口是 `OnNetSpawned` 之后 到 `OnNetDestroy` 之前**。在 `Spawn` 前读取（如 `Awake`），属于未初始化区，只能拿到类型默认值，行为不可靠。

### Lua 赋值与读取
使用 `GetValue()` 和 `SetValue()` 对变量赋值与获取。无法直接用等号（=）给变量赋值。

```lua
function OnNetSpawned()
    local val = vectorValue:GetValue()
    if self:HasOwnership() then
        vectorValue:SetValue(UnityEngine.Vector3(1,2,0))
    end
end
```

**非主权方触发**：如果业务事件由非主权方触发（例如玩家点击自己客户端的按钮），必须通过 `SendMessageToOwner` 将请求转发给主权方，由主权方执行上述的写入流程。直接在非主权端写入会被 SDK 静默忽略。

## 监听变量变化

当变量被主权方改变后，房间内的其他所有玩家将会接收到变化。

### 回调形态差异
- **基础值同步变量**：回调会提供 `(当前值, 前一个值)` 两个参数，可以直接拿到变化前后的完整快照。
- **集合同步变量 (List / Dictionary)**：回调**无参数**（仅通知“发生了变化”）。SDK 不提供集合变化前后的快照；如需知道具体是哪个元素发生的变化，或者需要前值，需业务侧自行缓存并比对。

### Lua 监听
通过 `OnValueChange` 事件函数监听变化。
- **基础值**：回调参数为 `(当前值, 前一个值)`。
- **集合值**：回调**无参数**。需要前后对比时，业务需自行缓存快照。

```lua
function OnNetSpawned()
    intValue:OnValueChange(function(curVal, preVal)
        print("intValue changed: ", preVal, " -> ", curVal)
    end)
    
    listSync:OnValueChange(function()
        -- 集合变化回调无参数，需要遍历
        listSync:ForEach(function(value, idx)
            print("list index:", idx, "value:", value)
        end)
    end)
end
```

## 网络同步机制

同步变量属于 SDK 内置的**房间级同步通道**，业务侧只需要按 API 正确读写，不需要额外处理传输层。其核心网络同步行为如下：

- **主权方写入广播**：主权方写入数据后，SDK 会自动广播到所有客户端，且保证**不丢包**。
- **后加入客户端/断线重连**：新加入房间的玩家，或断线重连成功的玩家，SDK 会自动推送同步变量的当前快照。房间维度的状态不会因重连而丢失，业务侧也**不需要额外补发数据**。对于后加入的客户端，建议在 `OnNetSpawned` 之后再消费值或注册监听。
- **主权变更交接**：当主权发生转移时，新的主权方会自动接管写入责任。因此业务侧在写入前必须**实时检查主权**（`HasOwnership()`），不要缓存“我是主权方”的静态标记。
- **机制分工对比**：
  - **同步变量**：适用于房间级状态，需保证最终一致性的场景。
  - **脚本消息**：适用于事件驱动、一次性指令（如"播放特效一次"）。
  - **DouyinObjectSync**：适用于 Transform 位置 / 旋转的自动跟随。

## 生命周期

同步变量的生命周期依附于其所在的网络对象。在网络对象的生命周期内，同步变量的可用性存在严格的时序限制：

1. **`Awake / Start` 阶段（未就绪）**：
   - 此时可以读值，但值可能尚未从服务端同步下来，**读取到的值是不可靠的**。
   - **禁止**在此阶段进行写入。

2. **`NetSpawn` 动态对象回调（专属赋值窗口）**：
   - 这是一个特殊的时机。调用 `NetSpawn` 创建对象的客户端，可以在回调函数中给同步变量赋初始值。
   - 虽然此时本端尚未进入 `OnNetSpawned`，但在此回调中写入的值会**可靠地同步给所有客户端**。

3. **`OnNetSpawned` 到 `OnNetDestroy` 阶段（有效值窗口）**：
   - 这是同步变量的**唯一有效值窗口**。在此阶段内读值稳定有效。
   - **兜底触发**：在 `OnNetSpawned` 后，会对每个同步变量**至少触发一次**变化事件（即使主权方从未修改过）。这能确保业务侧在进入网络阶段时，状态能正确对齐初始值。
   - 强烈推荐将同步变量的监听注册（`OnValueChange`）统一放在 `OnNetSpawned` 中进行。

4. **`OnNetDestroy` 之后（销毁期）**：
   - 对象已进入销毁流程，不允许再进行读写，变化事件也不再触发。

## 集合同步变量 (List / Dictionary) 专属操作

集合类型同步变量不支持整体的直接赋值，而是通过专属 API 进行细粒度的操作。根据主权规则，操作被严格划分为读与写两类：
 
### 1. 读操作（非主权方与主权方均可调用）
- **读取单项**：`GetValue(index)` (List) / `GetValue(key)` (Dictionary)
- **获取元素个数**：`Count()` (List / Dictionary)
- **遍历**：`ForEach(func)` (List / Dictionary)
- **键存在判断**：`ContainsKey(key)` (仅 Dictionary)

### 2. 写操作（仅主权方可调用）
> **⚠️ 注意**：非主权方调用以下修改接口会被 SDK 静默忽略。非主权方如果需要修改，必须**将请求转发给主权方**（例如通过消息），由主权方执行写入。

- **修改单项**：`SetValue(index, val)` (List) / `SetValue(key, val)` (Dictionary)
- **清空**：`Clear()` (List / Dictionary)
- **追加**：`Add(val)` (仅 List)
- **指定位置插入**：`Insert(index, val)` (仅 List)
- **按索引移除**：`RemoveAt(index)` (仅 List)
- **按键移除**：`Remove(key)` (仅 Dictionary)


## 集合同步变量专属操作API速查

> **⚠️ 注意**：非主权方调用修改接口会被 SDK 静默忽略。

| 操作类型 | List | Dictionary | 权限要求 |
| --- | --- | --- | --- |
| **读取单项** | `GetValue(index)` | `GetValue(key)` | 全端可读 |
| **获取个数** | `Count()` | `Count()` | 全端可读 |
| **遍历** | `ForEach(func)` | `ForEach(func)` | 全端可读 |
| **修改单项** | `SetValue(index, val)` | `SetValue(key, val)` | **仅主权方** |
| **清空** | `Clear()` | `Clear()` | **仅主权方** |
| **追加** | `Add(val)` | / | **仅主权方** |
| **插入** | `Insert(index, val)` | / | **仅主权方** |
| **移除** | `RemoveAt(index)` | `Remove(key)` | **仅主权方** |
| **键是否存在** | / | `ContainsKey(key)` | 全端可读 |

## 避坑指南 (FAQ)

### 1. 非主权方调用赋值，“表面上没写进去”
**现象**：非主权端写入值，本端 UI 无变化，其他端也没有事件。
**原因**：基础和集合同步变量的写入权限**只属于主权方**。SDK 会忽略非主权方的写入。
**修复**：写入前用 `HasOwnership()` 判断；非主权方通过消息转发给主权方。

### 2. 赋值后立刻读值判断是否成功
**现象**：非主权方赋值后再读值，发现没变；主权方赋值后读值是新值。
**原因**：非主权方的写入被忽略。用读值判断“是否写入成功”逻辑不可靠。
**修复**：写入前判主权，状态的最终一致性永远由 `OnValueChange` 驱动表现刷新。

### 3. 主权可能在消息链路中发生迁移
**现象**：非主权方发消息给主权方要求写入，但目标端收到消息时主权已迁移，导致赋值静默失败。
**原因**：消息网络回程期间，主权可能发生了改变。
**修复**：在实际执行赋值的函数入口**再判一次**主权。

### 4. `Clear` 之后立刻批量 `Add`，造成 UI 闪烁
**现象**：主权方在一次业务事件中清空集合并批量插入，导致远端 UI 在很短时间内被刷新多次。
**原因**：每次集合结构变化都是独立一次同步与事件触发。
**修复**：在 handler 中做**整体重绘**（覆盖而非增量），或加一层防抖机制（下一帧统一渲染）；大规模数据考虑用 JSON 序列化成字符串整体同步。
