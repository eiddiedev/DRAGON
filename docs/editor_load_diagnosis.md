# 编辑器负载排查（2026-11-12，本地未推送）

## 发现
正式工程 scripts 有 239 个文件，共 202.03 MiB。当前 scene.data runtimeScripts 引用的导入目录是 prefab_1、2、7、8、9、26。另有 20 个历史导入目录，共 183.03 MiB；当前场景序列化脚本内容未发现指向这些历史目录的显式 imported/prefab 路径。

## 隔离对照
- 完整复制正式场景、scripts、settings、world-config、作者工作区、生成配置到“龙眠负载对照”。只把上述历史目录移动到工程外备份。
- 场景文件 SHA256 与正式工程一致；剩余 scripts 18.99 MiB。
- 副本加载就绪后主进程 CPU 约 3.2%–3.4%。
- 在同一副本放回 20 个历史目录，主进程升至约 179.5%，lsof 确认编辑器重新打开旧脚本。移出后当时仍在高负载处理，因此不能宣称热移除会即时恢复；随后停止隔离实例。
- 该结果支持“历史脚本扫描/文件变化处理是可减轻的负担”，不能证明这是所有镜头卡顿的唯一根因。正式编辑器主进程在采样期间也由约 160% 自行降至约 5%，可能存在扫描阶段结束的影响。

## 建议先做的可回退优化
保存后回主页，按当时最新 scene.data 再次核对脚本引用，把未引用的历史导入目录移到工程目录外的持久备份，保留当前脚本、模型、地形与摆放，再重新打开检查镜头。
不要在打开工程时直接批量删除，避免文件监听反复扫描；不要删作者工作区或当前 prefab_26。
若仍卡，再分开测编辑器主进程与渲染进程，评估内嵌大图片脚本和场景几何开销，不能只靠包体大小推断。
